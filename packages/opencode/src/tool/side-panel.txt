See and steer the IRIS Desktop side panel beside this conversation, and use it to SHOW the user things instead of describing where they are.

Many people do not know their way around the desktop app. When the user asks where something is or how to do something in the app ("where do I connect Gmail?", "how do I see my scheduled agents?", "show me my board", "where did that page go?"), take them there with this tool, then say in one short sentence what they are looking at and what to do next. Do not write out click-by-click directions for something you can open.

Also use it to show the result of your own work: open the artifact you just made, the board you saved to, the page you opened in the browser.

Call action=state first when you need to know what is on screen or which places exist — it returns the panel's current view and a map of every product and view with what each is for. Pick the place by its purpose from that map.

Actions:
- state: what the panel shows now (open or closed, tab, product › view, board, selected artifact, open card, browser address), plus the map of products and views. It asks the desktop live; if the desktop does not answer it returns the last report marked CACHED with its age (metadata.live=false, metadata.ageSeconds).
- open / close: open or close the side panel.
- show: surface (product id or label, e.g. "atlas", "Genesis", "agents", "integrations"), optional sub (view id or label, e.g. "schemas", "heartbeats", "add"), optional bloq (board id).
- artifact: id — Genesis › Artifacts with that genesis_artifact selected.
- card: bloq (board id) and item (card id), optional list — Atlas on that board with that card open, the same as the app's link https://heyiris.io/atlas?project=<bloq>&row=<list>&card=<item>. Use this to show a card you just saved; sub only takes view ids.
- tab: tab = "review" (Files & changes) or "context".
- browse: url — an http(s) address in the panel's Browser tab.

Every change returns what the desktop reports AFTER applying it; describe that, not what you asked for. If it reports an error, tell the user plainly. If the desktop does not answer, the result says what is known: whether any desktop is connected, how long it waited, when the panel last reported. A timeout is a failed round trip, not proof the user is away — try once more or call state before falling back to directions in words. Only when the result says no desktop is connected is the user certainly not looking at the panel. Change the panel only in service of what the user asked; do not move it around while they are working in it unasked.
